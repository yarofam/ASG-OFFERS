# ASG-OFFERS — инструкции для агентов (Claude / Codex)

Этот репозиторий раздаёт статические презентационные страницы под
конкретные предложения автомобилей (офферы) для B2B-покупателей через
GitHub Pages. Домен: **offers.asg-hub.com** (см. `CNAME`).

## Роль агента

Агент в этом репозитории — **публикатор готовых страниц**, не дизайнер.
Пользователь присылает готовый пакет под конкретный автомобиль — либо:

- **один standalone HTML-файл** (сгенерирован в Claude Design или аналогичном
  инструменте), либо
- **многофайловый пакет** (index.html + свои css/js/шрифты/изображения/данные,
  например архив на основе шаблона `templates/vehicle-offer-web/`).

Задача агента — только размещать эти файлы как есть:

- **Не редактировать** содержимое присланных файлов (HTML, CSS, JS, данные,
  ассеты) — ни вёрстку, ни стили, ни тексты, ни данные внутри `data/*`.
- **Не переписывать**, не "улучшать" ничего внутри пакета.
- Только копировать файл(ы) на нужный путь **с сохранением внутренней
  структуры и относительных путей пакета**, коммитить и пушить.
- Если это архив (zip) — распаковать и перенести всё дерево файлов целиком,
  не выборочно.
- Если в `index.html` встречается плейсхолдер `{{OFFER_URL}}` (используется
  в тегах Open Graph для превью ссылок в мессенджерах) — **не трогать его и
  не подставлять вручную**. Его заполняет автоматически workflow
  `.github/workflows/offer-link-previews.yml` после пуша, коммитом
  «Bake offer link-preview URLs».

### Правило: share.jpg (превью ссылки)

`share.jpg` — **не кадр обложки, пересохранённый в JPEG шириной 1200px**
(именно это правило и давало маленькие/некорректные превью в WhatsApp).
Карточка собирается на этапе сборки оффера из фото обложки под затемнением
в стиле hero, знака ASG **без подписи «Automotive Supply Group»** и полного
названия машины. Без цены, без строки цвета/комплектации, без пометки
confidential. `share-card.html`, если он пришёл в пакете, удаляется из папки
оффера перед публикацией — агенту нечего с ним делать, если он не пришёл.

Формат `share.jpg`:
- ровно **1200×630**, JPEG, до **300 КБ**.

В `<head>` каждого оффера обязательны, помимо `og:image`:
- `og:image:type` = `image/jpeg`
- `og:image:width` = `1200`
- `og:image:height` = `630`
- `og:image:alt`
- `twitter:image` — тот же `{{OFFER_URL}}/share.jpg` (или уже подставленный
  абсолютный URL, если бэйк уже прошёл).

Без объявленных `og:image:width`/`og:image:height` WhatsApp не показывает
большую карточку превью, а только мелкую иконку-ссылку.

**Превью кешируется по URL.** Если карточка (`share.jpg`) в оффере меняется,
ссылка с тем же slug продолжит показывать старое превью в мессенджерах
неделями — для изменённой карточки нужен новый slug (см. «Процесс публикации
нового оффера»), а не редеплой по старому пути.

## Структура репозитория

```
/o/<slug>/                     — страница одного оффера (папка на оффер)
/o/<slug>/index.html           — вход в оффер; остальное — по структуре
                                  присланного пакета (assets/, css, js, data/…)
/templates/vehicle-offer-web/  — эталонный шаблон/дизайн-система оффера
                                  (справочный материал, не публикуется как
                                  live-страница напрямую)

index.html                     — каталог на корне домена; ГЕНЕРИРУЕТСЯ из
                                  templates/catalog/index.html, руками не
                                  редактируется
/templates/catalog/            — шаблон каталога от дизайн-системы:
                                  index.html с метками + README.md (контракт)
catalog.css / catalog.js       — оформление и логика каталога (дизайн-система,
brand-interaction.css             не править руками)
catalog.json                   — настройки каталога (цены, порядок, скрытые
                                  офферы, подмена фото)
share.jpg                      — превью ссылки самого каталога (1200×630)
assets/Onest.ttf, assets/brand/ — шрифт и знак ASG для каталога
assets/media/<slug>.webp       — фото карточек; ГЕНЕРИРУЮТСЯ, не править
favicon.svg / favicon-32.png / apple-touch-icon.png
package.json                   — sharp для сборки фото карточек
tools/build-catalog.mjs        — сборщик каталога
tools/share-card.html          — исходник превью-карточки (лежит в tools/,
                                  чтобы корень сайта его не раздавал)

CNAME                          — домен GitHub Pages (offers.asg-hub.com)
README.md
AGENTS.md                      — этот файл
CLAUDE.md                      — подключает AGENTS.md для Claude Code
```

Каждый оффер живёт в собственной папке `/o/<slug>/`. Если оффер — один HTML-
файл, это просто `/o/<slug>/index.html`. Если оффер — многофайловый пакет,
всё его дерево (index.html, assets/, *.css, *.js, data/…) кладётся внутрь
`/o/<slug>/` с сохранением относительных путей, как в присланном пакете.
Итоговый URL оффера: `https://offers.asg-hub.com/o/<slug>/`.

**Важно: папки офферов самодостаточны.** Общие css/js/шрифты/ассеты
намеренно дублируются в каждой `/o/<slug>/` (никаких общих/шаренных путей
типа `/assets/shared/`, никаких симлинков и никаких ссылок из одного
оффера на файлы другого). Так изменение или удаление одного оффера
никогда не ломает другой.

## Правило генерации slug

- Длина: **6 символов**.
- Алфавит: буквы (латиница, нижний регистр) + цифры.
- Не должен быть последовательным или угадываемым (не `aaaaaa`, не `111111`,
  не `abc123`, не инкремент от предыдущих slug'ов).
- Перед использованием проверить, что папка `/o/<slug>/` ещё не существует
  в репозитории — при коллизии сгенерировать другой slug.

## Процесс публикации нового оффера

1. Сгенерировать новый slug по правилу выше.
2. Создать `/o/<slug>/` и перенести туда присланный пакет без изменений:
   - один файл → `/o/<slug>/index.html`;
   - многофайловый пакет/архив → распаковать всё дерево внутрь `/o/<slug>/`,
     сохранив относительные пути (assets/, *.css, *.js, data/… и т.п.).
3. Закоммитить и запушить в `main` (или в ветку, указанную в задаче).
4. Каталог на корне домена обновится сам — руками `index.html` не трогать
   (см. «Каталог»).
5. Сообщить пользователю итоговую ссылку:
   `https://offers.asg-hub.com/o/<slug>/`

## Процесс удаления оффера

1. Удалить папку `/o/<slug>/` целиком.
2. Закоммитить и запушить в `main`.
3. Каталог перестроится сам и машина исчезнет с витрины.
4. Подтвердить пользователю, что ссылка деактивирована.

## Каталог (витрина на корне домена)

`https://offers.asg-hub.com/` — общая витрина всех опубликованных офферов.
Одна ссылка для брокеров и агентов вместо рассылки отдельных ссылок на каждую
машину.

**`index.html` в корне генерируется — редактировать его руками нельзя.**
Дизайн каталога пришёл из дизайн-системы и лежит в `templates/catalog/` —
это шаблон с метками, его тоже руками не правят (правки идут через
дизайн-систему). `tools/build-catalog.mjs` подставляет в шаблон то, что лежит
в `o/`, и записывает результат в корневой `index.html`. Запускает это workflow
`.github/workflows/offer-link-previews.yml` на каждый пуш, одним коммитом с
бэйком `{{OFFER_URL}}`. Локально: `npm install && node tools/build-catalog.mjs`.

Контракт шаблона (подробно — в `templates/catalog/README.md`):

- содержимое между `<!-- ASG:FILTERS:START/END -->` и
  `<!-- ASG:CARDS:START/END -->` заменяется целиком;
- `{{COUNT}}` и `{{UPDATED}}` заполняет сборщик;
- `{{SITE_URL}}` (3 места в `<head>`) заполняет workflow — как `{{OFFER_URL}}`
  в офферах;
- `id="grid"`, `id="filters"`, `id="gridEmpty"`, `data-brand` на карточке и
  `data-filter` на чипе — служебные, на них держатся фильтр и счётчики;
- CSP `default-src 'none'`: ни инлайновых `style=`, ни инлайновых `<script>`
  в том, что генерируется.

Что сборщик берёт из оффера (сами файлы оффера при этом не меняются):

- название, спецификацию одной строкой, цену и статус — из
  `o/<slug>/data/offer.js` (файл исполняется, а не парсится регулярками:
  синтаксис в пакетах разный);
- если `data/offer.js` нет (оффер одним файлом) — из og-тегов `index.html`;
- фото карточки — hero этого оффера, пережатый в `assets/media/<slug>.webp`
  (900×563, WebP, до 100 КБ) через `sharp`. Миниатюра из `thumbs/` берётся
  только если этот файл реально есть в галерее оффера: в некоторых пакетах
  в `thumbs/` лежат чужие остатки от шаблона (в `o/8sq511/` — `thumbs/hero.webp`
  от Ferrari). Фото удалённых офферов сборщик удаляет сам.

Если `sharp` не установился, сборка не падает: остаются уже закоммиченные
фото, а для нового оффера карточка сошлётся на полноразмерный hero.

Настройки — в `catalog.json` (тексты шапки живут в шаблоне, не здесь):

- `showPrices` — `false` убирает цены со всех карточек («On request»);
- `order` — слаги, которые идут первыми; остальные сортируются по дате
  публикации, новые сверху;
- `hidden` — слаги, которые не показывать на витрине (сам оффер по прямой
  ссылке продолжает работать);
- `images` — если hero оффера плохо читается карточкой, здесь можно указать
  другой файл **внутри папки оффера** (путь относительно `/o/<slug>/`).

Превью ссылки каталога — `share.jpg` (1200×630), исходник в
`tools/share-card.html`. **Счётчика машин и даты на карточке нет намеренно:**
мессенджеры кешируют превью по URL, URL каталога не меняется никогда, и любое
число, вшитое в картинку, через неделю будет врать.

Каталог, как и офферы, отдаётся с `noindex, noarchive` — он не для поиска, а
для прямой ссылки.

### 2026-09-21 — Claude (каталог на корне домена)
Корень `offers.asg-hub.com` больше не пустой: там витрина всех офферов
(тёмная, в той же дизайн-системе, что и страницы офферов — Onest, iron/mineral,
оранжевый signal). Карточка = hero машины, марка, модель, спецификация строкой,
цена net и статус; клик — на сам оффер. Есть фильтр по марке.

Генерация автоматическая: `tools/build-catalog.mjs` собирает `index.html` из
`o/`, workflow переименован в «Publish offers» и делает бэйк `{{OFFER_URL}}`
и пересборку каталога **одним коммитом** (иначе два пуша в одном воркфлоу
дрались бы за push). `actions/checkout` переведён на `fetch-depth: 0` —
сортировка «новые сверху» смотрит на коммит, которым появилась папка оффера.

Решения, которые стоит помнить:
- дубликаты каталог НЕ склеивает и не должен: одна папка в `o/` — одна
  карточка. Две похожие машины (два Cullinan) — это два оффера, так и надо.
  Правка существующего оффера = замена содержимого его папки (URL и место в
  каталоге сохраняются); новая машина или новая версия спецификации = новый
  slug; снять с витрины, не убивая ссылку, — `hidden` в `catalog.json`;
- цены на витрине показываются; выключаются одной строкой `showPrices: false`
  в `catalog.json`;
- витрина сознательно оставлена без регистрации и без пароля (статика на
  Pages, пароль там — театр), защита — `noindex` + то, что ссылку даём сами;
- картинки карточек берутся из офферов по ссылке, а не копируются в корень:
  каталог всё равно пересобирается на каждое изменение `o/`.
